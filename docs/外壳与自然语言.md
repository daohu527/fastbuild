# 自然语言需求、自动布局与外壳固定方案

## 输入层次：位置不是用户必须给的参数

原 `examples/design.yaml` 的 `position` 是器件局部原点在底板上的 XY 坐标，
属于低层几何指令。它仍保留兼容，但不是新的产品设计入口。

新的流程：

```text
自然语言需求 brief.md + 器件接口 components.yaml
                |
       本地 LLM 或人工翻译为意图
                |
       审阅 intent.json，确认假设
                |
   自动排布及尺寸推导 → 外壳/固定件/开孔
                |
   几何检查 → STEP / BOM / 离线预览
```

自然语言表达“需要什么”，接口清单提供“器件客观是什么”，意图文件是可审阅、
可重复执行的中间产物，不应要求普通使用者逐项编写它。

## 1. 不依赖模型，先看外壳实际效果

当前开发机已安装依赖并完成 CSV 准备，使用 `.venv311`。
新环境按 README 安装后先执行 `python tools/prepare_enclosure.py`。

```bash
# 若还没有合成器件，先运行；已有目录不能重复覆盖。
.venv311/bin/fastbuild demo --output build/demo

# 下方命令使用已审阅示例计划；已有 demo 时从这里开始。
.venv311/bin/fastbuild enclose examples/enclosure-brief.md \
  --components examples/components.yaml \
  --plan examples/enclosure-intent.json --accept-plan \
  --output build/my-enclosure
```

`--accept-plan` 表示确认计划对需求的解释，不是豁免几何检查。
几何检查失败时仍会报错并返回非零。

示例需求在 `examples/enclosure-brief.md`：

> 为控制板和传感器设计 FDM 原型外壳。沿 X 并排自动布局，包络间留 8 mm，
> 壁厚 3、底厚 6、盖厚 3、柱高 8 mm。顶部可拆盖带定位裙边，
> 器件和上盖使用 M3 螺栓螺母固定。前壁五个通风孔。
> 整体含安装耳和紧固件不超过 180×150×70 mm。

本例仍使用合成测试件；需求没有要求连接器开口。内部 connector 禁入区
不等于连接器可从外部插入，也不代表通风性能已验证。

## 2. 换成实际器件

创建一个目录，放入 brief、清单及器件 STEP。清单不包含底板坐标：

```yaml
units: mm
devices:
  - name: controller
    step: controller.step
    mount_hole_diameter: 3.4
    mounts: [[-14, -10], [14, -10], [-14, 10], [14, 10]]
    keepouts:
      - name: connector
        min: [-8, 15, 0]
        max: [8, 27, 8]
  - name: sensor
    step: sensor.step
    rotation_deg: 90
    mount_hole_diameter: 3.4
    mounts: [[-10, -8], [10, -8], [-10, 8], [10, 8]]
```

孔位是**器件自身坐标系中的客观接口数据**，不是产品中最终安装位置。
应来自供应商图纸或 CAD 测量，不允许 LLM 猜测。
`rotation_deg` 可选，默认为 0；当前自动布局不搜索最佳旋转。
禁入区也在器件局部坐标中，程序会在布局时计入其包络。

程序按器件包围盒、禁入区和螺母工具包络计算布局及壳体尺寸。
目前支持 X/Y 单排，按清单顺序排列，不是任意空间的最优装配规划。

真实器件当前仍需满足：

- 一个 STEP 对应一个有效实体；
- 安装底面为局部 Z=0，安装孔竖直贯穿；
- 安装孔下方有足够的平面支撑区；
- 该通孔螺栓方案还要求孔上方有同一最高平面的螺母座面。

最后一条意味着带高大元件的复杂 PCB 可能不适用当前模板。
程序会拒绝悬空螺母，而非把它放在最高元件上方。
后续应扩展每个安装孔的局部座面高度、热熔嵌件或可拆托架，
不要通过篡改器件外形绕过检查。

## 3. 用自然语言生成设计意图

使用已安装并启动的本地 Ollama 模型：

```bash
.venv311/bin/fastbuild plan my-design/brief.md \
  --components my-design/components.yaml \
  --model YOUR_LOCAL_MODEL \
  --output build/intent-01.json
```

`YOUR_LOCAL_MODEL` 替换为本机实际可用、能遵循 JSON Schema 的模型名称。
程序不会下载模型或自动连接任何云端服务。
请求固定发送到 `127.0.0.1:11434`，禁用环境代理和 HTTP 重定向。
只发送需求文本和器件名称，不发送 STEP 文件、安装孔表或本地模型路径。

输出包含：

- `intent`：模板、布局轴、厚度、间隙、最大尺寸、矩形开孔和需求解释；
- `unresolved_requirements`：不能实现或存在歧义的要求；
- 需求及清单文件的 SHA-256，防止改了输入仍复用旧计划；
- 使用的模型名称。

模型声明未解决要求、返回未支持字段、无效数字或非 JSON 时会报错，
不会自动回退成示例外壳。**但模型仍可能遗漏原文要求，Schema 无法检查全部语义。**
必须对照需求审阅 `interpreted_requirements`、尺寸和开孔，确认后执行：

```bash
.venv311/bin/fastbuild enclose my-design/brief.md \
  --components my-design/components.yaml \
  --plan build/intent-01.json --accept-plan \
  --output build/product-01
```

没有本地模型时，可以由工程师或现有 Agent 参考 `examples/enclosure-intent.json`
整理意图文件，然后执行同一命令。仅更改 brief 而沿用手工计划，
**不会自动改变几何**，报告会标明该路径不是自动文本理解。

## 4. 当前支持的外壳和固定方案

| 功能 | 实现 |
|---|---|
| 壳体 | 复用固定提交的 cq_enclosure_builder，融合面板形成单实体开口盒 |
| 底部结构 | 一体底板及安装柱，底厚不小于壁厚 |
| 器件固定 | ISO 4017 M3 六角头螺栓由下向上，底部六角限位孔，上方 ISO 4032 螺母 |
| 盖板 | 顶部独立可拆盖，1.5 mm 定位裙边，径向间隙 0.3 mm |
| 盖板固定 | 四个外置安装耳，同样采用 M3 螺栓螺母 |
| 紧固件 | cq_warehouse 标准件，自动选择足够长度的标准螺栓 |
| 开孔 | 前后左右壁上的矩形开孔，或指定节距的重复长孔 |
| 检查 | 单实体有效性、器件/壳/盖/紧固件穿透、孔及座面、禁入区、开孔边距、局部工具空间、整体尺寸 |

六角孔为螺栓头限位而非螺母热熔孔，使用 0.4 mm 直径方向的原型间隙。
标准间隙孔为 3.4 mm。应按打印机、材料和实物试配调整，不保证打印即合格。
底部螺栓头口袋上方至少留 1.5 mm 材料。
紧固件使用简化螺纹，未计算预紧力、扭矩和抗松动性能。

器件螺母上方检查半径 6 mm 的竖直工具空间，检查时上盖已移除。
这不是完整的插入、旋拧、拆装路径证明。装配前应先从底部穿入器件螺栓，
再装器件及上方螺母，最后安装上盖。

开孔中心 Z 从**外壳外底面**计算；front/back 对应 -Y/+Y，
left/right 对应 -X/+X。front/back 的 offset 沿 X，left/right 沿 Y。
开孔边距和重复孔之间的 web 至少 2 mm，前后壁还需避开上部安装耳区域。
这些参数是接口尺寸，不是要求用户指定器件在底板上的位置。

## 5. 完成判定与查看

命令成功返回 `geometry_passed`，退出码为 0，且生成 `validation.json`。
报告内 `not_checked` 不为空是预期行为，不能视为工程放行。

```text
product-01/
├── assembly.step          # 包括所有紧固件的完整装配
├── exploded.step          # 上盖及对应紧固件抬起的示意，不是装配路径仿真
├── body.step              # 独立盒体
├── lid.step               # 独立上盖
├── preview.html           # 本地浏览器打开，不需要服务
├── assembly.svg
├── exploded.svg
├── bom.json               # 标准件规格/数量及壳盖
├── brief.md
├── intent.json
├── components.yaml        # 绝对路径器件清单快照
├── resolved-layout.yaml   # 程序推导的低层坐标，非用户必填输入
└── validation.json
```

浏览器直接打开 `preview.html`，看到静态线框装配图及开盖图；不是可旋转 Web 3D。
交互查看使用 FreeCAD 打开 `assembly.step` / `exploded.step`。
远程使用时下载整个结果目录，避免 HTML 找不到相邻 SVG。

BOM 是当前模板的壳盖及紧固件清单，不包括器件采购料号、线束和完整采购属性。
STEP 不是 FreeCAD 原生特征历史；重新生成仍需保留 STEP 输入及计划。

## 6. 仍不支持的“复杂设计”

当前只扩展到**带固定方案的仪器盒模板**，并非通用生成式机械设计系统。
尚不支持卡扣/铰链、曲面外观、钣金折弯、热熔嵌件、密封槽及 IP 等级、
EMC 设计、复杂曲面配合、自动连接器识别、热流场和 FEA 放行。
这些要求需要新模板和专门校验，不能靠提示词自动获得可靠实现。

本轮已实测经过审阅计划的外壳链路；自然语言接口使用受控响应测试了协议、
Schema 和失败行为。开发机没有 Ollama/本地模型，**尚未验证真实模型的中文理解效果**。
下一步应以真实器件和明确的制造/固定需求校准，而不是把示例视为生产方案。
