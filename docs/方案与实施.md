# 从器件数模生成装配与支架：开源调研及实施方案

调研日期：2026-11-05。能力依据官方仓库 README、依赖声明和部分关键代码；
仓库存在、文档声称支持，不等于已经在本项目验证。实际验证范围单独记录。

## 1. 目标与结论

输入几个器件的 STEP 数模，补充安装接口、布局要求、禁入空间及制造约束，
通过参数化模板生成产品安装结构，导出装配和零件 CAD，再开展工程检查。

不从零开发几何内核、不训练 CAD 大模型、不重写通用 Agent 框架。
推荐 CadQuery + OpenCascade + Python/YAML/JSON Schema；以 FreeCAD 做检查及
FEM 入口，LLM 负责选模板和提出参数，确定性程序负责几何与工程判定。

本次调研尚未找到已验证覆盖“任意器件输入 → 自动装配 → 自动设计支架 →
工程校验 → CAD 导出”全过程的成熟开源产品。可行路线是复用各环节，
补充安装语义、布局策略和规则，而不是让 LLM 从几何外形猜完整工程意图。

## 2. 可复用项目

| 项目 | 能力 | 采用方式及边界 |
|---|---|---|
| [CadQuery](https://github.com/CadQuery/cadquery) | STEP、参数化实体、装配约束、CAD 导出 | 主建模框架，Apache-2.0 |
| [CadQuery MCP](https://github.com/CadQuery/cadquery-contrib/tree/master/mcp-server) | render、inspect、get_parameters、export；装配 STEP 保留名称、颜色、位置 | 直接复用 AI 工具入口；没有现成碰撞规则或 FEA |
| [cq_enclosure_builder](https://github.com/raphael-isvelin/cq_enclosure_builder) | STEP 自定义部件、面板、外壳、布局、PCB 固定和支撑 | 外壳入口已复用壳体；Apache-2.0；上游主导出为 STL，本项目接出 STEP |
| [cq_warehouse](https://github.com/gumyr/cq_warehouse) | 标准紧固件、标准孔和装配辅助 | 当前直接依赖其标准孔径数据和标准件 API；Apache-2.0 |
| [CICADA](https://github.com/Oaklight/cicada) | 代码生成、执行调试、多视角反馈、Agent 编排 | MIT；实际 codecad 依赖 build123d，不是开箱即用的 CadQuery 框架 |
| [FreeCAD MCP](https://github.com/bonninr/freecad_mcp) | 读取场景、执行 FreeCAD Python | MIT；控制桥接，不自带完整工程检查 |
| [CADAM](https://github.com/Adam-CAD/CADAM) | 文本/图片建模、Web 预览、参数调整 | GPL-3.0；采用 OpenSCAD，列出的导出为 STL/SCAD/DXF，不作为 STEP 主链路 |
| [bracket_pipeline](https://github.com/Radinium/bracket_pipeline) | FreeCAD → Gmsh → CalculiX → 应力/位移/质量 → 参数优化 | MIT 许可证文件；参考 FEA 流程，不直接当生产级求解平台 |

不能仅凭 GitHub 仓库级许可证标签作判断。

## 3. 架构与职责

```text
STEP 器件 + 安装语义 + 设计要求
                  |
        YAML / JSON Schema 校验
                  |
    LLM 选模板、提出布局和参数（后续）
                  |
    确定性布局规则 / 装配约束求解
                  |
       CadQuery 生成安装结构
                  |
      几何检查 + 多视角反馈
                  |
       FreeCAD 复核 / FEA
                  |
   装配 STEP + 零件 STEP + 参数 + 报告
```

| 工作 | 执行者 |
|---|---|
| 理解接口朝向、维护便利性等要求 | LLM + 人工确认 |
| 选择底板、L 型支架、抱箍等模板 | LLM + 已验证模板库 |
| 孔位变换、实体计算和尺寸运算 | Python + CadQuery |
| 给定配合关系后的位姿求解 | CadQuery 装配约束 |
| 碰撞、间隙、壁厚、边距判定 | 确定性规则 |
| 强度、位移和稳定性 | 工程计算及 FEA |
| 最终放行 | 工程师 |

CadQuery 的装配求解器不等于通用空间布局规划器。第一阶段显式输入布局，
避免把“按坐标放好器件”描述为“自动发现最优装配”。

## 4. 输入契约

第一阶段只接受 STEP 实体。STL 仅适合预览或非精密参考，不作为安装孔依据。

- 统一 mm、局部坐标与安装方向。
- 显式声明安装孔位置和孔径；几何程序验证，不从截图估测。
- 指定接口插拔、散热和布线禁入区。
- 指定整体尺寸、最小间隙、安装柱高度和外径。
- 第一阶段采用一体底板/安装柱模板、Z 向贯穿安装孔、XY 平移/Z 轴旋转。
- 后续补充制造方式、材料、质量/重心、载荷工况和允许位移。

安装底面必须为器件局部 Z=0；安装柱在其下方。若源模型坐标不符合要求，
需先用 CAD 工具变换并另存，不静默归一化，以免破坏接口坐标语义。
安装孔适配暂时由人工提供，后续可“识别候选 → 人工确认”。

## 5. 分阶段实施

### 阶段一：确定性几何闭环（本轮实施）

实现配置校验、STEP 导入、显式布局、一体底板/安装柱、cq_warehouse 标准间隙孔、
几何检查、独立零件及装配 STEP 导出、重新导入校验。
提供两个合成器件，证明流程可执行，不把它们称为供应商模型。

本阶段为最小底板模板，不强行依赖旧外壳库的 UI 或安装脚本。
这是范围选择，不是替换开源底座：几何、标准件和 CAD 交换复用现有库。
安装柱仅含贯穿间隙孔，未建模螺纹/嵌件、螺母或锁紧结构；
不能据此认定形成完整可用的紧固连接。

输出：

- `assembly.step`：保留组件的装配，不将整个产品布尔融合；
- `mounting_plate.step`：独立安装结构；
- `design.yaml`：解析后的绝对输入路径及参数；
- `validation.json`：检查、未执行项、输入 SHA-256、尺寸及体积。

### 阶段二：现有 Agent 与模板闭环

复用 CadQuery MCP；Agent 先只调整模板和 YAML，不任意重写整个建模程序。
输入检查结果、多视角图和尺寸信息，有限次迭代，失败时输出原因。
生成 Python 必须隔离执行，限制文件、网络、执行时长及资源。

引入 cq_enclosure_builder 的 STEP 部件/PCB 固定例程，先测试兼容性再集成；
它存在额外紧固件 CSV 安装步骤，不假设与最新 CadQuery 开箱兼容。
其默认 STL 导出不能替代本项目的 STEP 交付。

### 阶段三：工程检查与 FEA

使用 FreeCAD FEM + Gmsh + CalculiX；先对新生成支架做线性静力分析，
材料、固定面、受力面和工况必须明确。参考 bracket_pipeline 的执行组织，
但不能沿用固定 `Face1` / `Face5` 编号；参数变化后必须通过接口位置和法向重新定位。

求解失败、材料缺失或网格不收敛必须报告失败/未检查，不得回填“合格”数值。
补充网格收敛性、多个工况和工程审核后，再考虑 SciPy 参数优化；
不在第一版做拓扑优化和整机接触分析。

## 6. 重要边界

1. STEP 不携带 CadQuery 完整建模历史。Python + YAML 才是参数化来源。
   将 STEP 保存成 FCStd 不会自动恢复 FreeCAD 的草图/拉伸特征树。
2. CadQuery 与 FreeCAD 都使用 OpenCascade，FreeCAD 重导入有实用价值，
   但不是独立几何内核的交叉认证。
3. 不碰撞不等于装得进去。安装方向、工具空间和拆卸路径必须单独检查。
4. FEA 不替代实测。FDM 层间各向异性、蠕变和打印方向不应被忽略。
5. 标准间隙孔数据不是打印公差补偿，也不代表紧固连接已经验证。
6. 第一阶段不生成完整工程图、GD&T、钣金展开或原生商业 CAD 特征树。

## 7. 验收与预计投入

| 检查项 | 条件 |
|---|---|
| 输入 | 坐标、单位正确，实体有效，安装孔与支撑面符合声明 |
| 结构 | 安装柱落在底板内，存在合理壁厚，孔对齐 |
| 装配 | 无非预期重叠，满足器件间隙及声明的禁入区 |
| 参数化 | 修改间距、旋转、板厚后可重算 |
| 交付 | STEP 可重导入，实体数、体积和位置一致 |
| 错误行为 | 配置、几何或导出失败时明确报错，不产出成功报告 |
| 后续工程验收 | 安装路径、工艺、紧固连接、载荷和 FEA 另行验证 |

在模型干净、安装接口已知、单一工艺的前提下，熟悉 Python/CAD 的工程师
可按约 5–10 个工作日规划首轮 PoC。此为估算，不是项目实测保证，
也不包含生产可靠性、认证或任意器件自动识别。

## 8. 本轮实施结果

已落地阶段一的 CLI、配置 Schema、几何规则、标准孔径复用及 STEP 交付；
已安装并通过真实 stdio 会话接通上游 MCP 的 inspect、SVG render、export，
并确认错误调用返回错误标记。没有调用任何云端模型。

本机验证使用隔离 Python 3.11.18 环境 `.venv311`，未修改系统 Python。
25 项测试通过，Ruff 检查和格式检查通过，78 个已安装依赖兼容；
上游 cq_warehouse 存在 `importlib.resources.open_text` 弃用警告，未屏蔽。
测试覆盖多根 STEP 不丢件、实际 CAD 重导入及位置保持、几何错误拒绝、
参数快照、CLI 和上游 MCP 集成。

本机持久化成果为 `build/verified/assembly.step`、
`build/verified/mounting_plate.step`、参数快照和检查报告。
源合成器件位于 `build/demo/inputs/`；`build/` 为忽略的本地生成目录，
不提交生成 CAD 二进制，其他机器按 README 重建。

可在当前环境用新输出目录重新生成：

```bash
.venv311/bin/fastbuild build examples/design.yaml --output build/my-design
```

FreeCAD 未安装，检查宏仅做语法验证，未执行 FreeCAD 重导入或 FEA。
真实器件适配、LLM 决策闭环、完整紧固连接、装配路径和制造验证仍属于后续阶段；
当前成果不能作为产品工程放行依据。

## 9. 需求升级：自然语言与外壳固定方案

后续实现已不局限于底板：新增 `plan` / `enclose` 命令，以及自然语言 brief、
器件接口清单和可审阅设计意图三层输入。器件安装孔仍为局部接口数据，
不再要求用户提供全部器件在产品中的 XY 位置。

壳体实际调用 cq_enclosure_builder，按上游说明安装自定义紧固件 CSV；
融合上游面板后加底部安装柱、顶部定位裙边、四个外置盖板安装耳，
并调用 cq_warehouse 的 ISO 4017 六角头螺栓与 ISO 4032 螺母形成几何连接。
自动选取标准螺栓长度，增加底部六角头限位孔，检查座面及局部工具空间。
支持四面矩形开孔及重复通风槽，输出装配/开盖 STEP、独立壳盖、BOM 及静态离线预览。

示例实际生成 28 个组件：壳体、上盖、两个合成器件、12 个螺栓和 12 个螺母。
整体含安装耳及紧固件约 90×83×41.5 mm。
明确审阅的计划可以直接运行，本地 Ollama 自然语言接口已实现协议与失败行为测试，
但本机没有实际模型，不能宣称已验证任意中文需求的理解和生成质量。

支持范围仍是可拆盖仪器盒模板，不涵盖卡扣、防水、曲面、热熔嵌件或 FEA；
完整装配路径、预紧力、打印公差和实物适配尚未验证。
LLM 可能遗漏原文要求，因此执行前必须人工审阅，并显式传入 `--accept-plan`。
完整命令、接口约束及当前限制见 [外壳与自然语言.md](外壳与自然语言.md)。

本轮验证结果：42 项测试通过，Ruff 规则及格式检查通过，79 个依赖兼容；
外壳示例持久化于 `build/enclosure-v2/`，可直接打开其中 `preview.html`，
或在 FreeCAD 中打开 `assembly.step`。预览是静态线框图，不是 Web 3D 编辑器。
